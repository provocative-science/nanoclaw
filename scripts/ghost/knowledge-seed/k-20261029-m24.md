At startup on 2026-10-29 (~12:39 UTC) Woody could not actuate `desorb_tube_extraction_gas_out_valve` (V20); other valves worked. Root cause (confirmed by Spark): commit `731e0e8` (Oct 28, "drive extraction gas out on OD6", live since the 21:03 UTC controller restart) moved the valve from panel riser 5 OD7 (manifold 1 pin 16) to OD6 (manifold 1 pin 15, a spare coil). The valve is still plumbed to pin 16, so commands energised the spare coil. Telemetry readback kept following the command because it reads the same remapped pin. Fixed by `9256f09` (back to OD7, restart 13:40 UTC).

Ghost blamed the overnight supervisor lock instead; that lock had already been cleared at 12:31 UTC (the S3 archive it read lagged by ~1h, so say "as of the newest sample" for airbed state, which is not in Prom).

How to check next time: when an output is commanded but nothing moves and its readback follows the command, run `mcp__telemetry__recent_changes(host, at, signals=[that output])` and look for a pin remap on it.
