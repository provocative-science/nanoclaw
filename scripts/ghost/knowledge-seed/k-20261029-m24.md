2026-10-29 05:42:22 UTC airbed lock. Root cause (confirmed by Spark): commit `731e0e8` (Oct 28, "drive extraction gas out on OD6") moved `desorb_tube_extraction_gas_out_valve` from panel_station riser 5 OD7 to OD6. Riser 5 also carries `vent_or_bag_valve`. The build went live with the controller restarts that ended 21:03 UTC. At 05:42:20 the riser-5 fields (and ~45 panel fields) went null, `extraction_bag_watchdog` tripped on its missing `vent_or_bag_valve` input, and `extraction_bag_recovery` kept failing with `Modbus(Device(MemoryParityError))`. Swapping the pin back (`9256f09`, restart 13:40 UTC) resolved it.

Lesson: the Modbus/parity errors and the station dropout were symptoms. A fault on a device whose I/O mapping changed in a recent deploy is a code problem until proven otherwise. Run `mcp__telemetry__recent_changes` (or read `change_check` in `why_locked`) before blaming hardware, quote the remap, and ask the author whether it matches the wiring.
