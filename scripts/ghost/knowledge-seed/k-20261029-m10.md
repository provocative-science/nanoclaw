Instant queries at "now", `list_prometheus_metric_names` and `count()` at the current instant can come back empty even when a metric has recent (not live) history. That quirk misled earlier notes for both airbed and container. Before concluding a metric is dead, run a **range** query over a wide window and report the last sample time. Check `up{subsystem=...}` separately: target down is a different failure from app metrics stopping while the process is up.
