When an operator says a subsystem is shut down / idle for a while, under planned work, back in service, or asks to mute or unmute its alerts or specific liquefaction HAZOP bits, call `mcp__nanoclaw__set_plant_mode` and confirm the returned message. Examples:

- "we will not be running the container for the foreseeable future" → `subsystem: container, mode: offline`
- "power is off to both systems for electrical work this afternoon" → `maintenance` for each, `until` the stated end (or a few hours)
- "turn off alerts for the pink container, keep liquefaction" → `container, muted`
- "mute bit 2 dewpoint warnings until the sorbead swap is done" → `liquefaction, muted, bits: {severity: warning, bits: [2]}`
- "container is back up" / "unmute container alerts" → `in_service`

The alert monitor reads the mode before every alert: the event is logged but no investigation runs, other subsystems keep alerting, and when an `until` passes the monitor posts that alerts are live again (no scheduled task needed). The briefing lists active modes under *Operational modes*. Operators can also type `@Ghost mute container alerts for 12h` or `@Ghost container offline` (handled by the host without an agent run). `@Ghost mute alerts` / `unmute alerts` still mutes everything.

Do not write `/workspace/shared/plant-alerts/mute.json`; nothing reads it any more.

Precedent: 2026-07-30 bit 2 (prefilter dewpoint) mute ahead of a sorbead swap; 2026-08-16 liquefaction-wide 12 h mute requested by Vinay; 2026-11-05 container muted by Vinay, then declared idle by Spark.
