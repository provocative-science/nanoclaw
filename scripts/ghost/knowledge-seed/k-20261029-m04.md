Separate from the host-wide "mute alerts" / "unmute alerts" command (handled by NanoClaw itself). When an operator asks to mute a subsystem or specific HAZOP bit(s) (e.g. "mute liquefaction alerts for 12 hours", "mute bit 2 dewpoint warnings until turned back on"):

1. Write/update `/workspace/shared/plant-alerts/mute.json`:
   `{"muted_subsystem": "liquefaction" | omit and use "muted_bits": [2], "silent": true|false, "reason": "...", "muted_at": "<ISO-UTC>", "muted_until": "<ISO-UTC>" (omit = until unmuted), "muted_by": "<name>"}`
   `silent: true` = no Telegram output, silent archive only; false/omitted = one-line summary instead of a full brief.
2. Every alert turn checks this file first (next to `latest.md`). If the alert's subsystem/bit matches and `muted_until` has not passed: still gather evidence and write `latest.md` / append `log.jsonl`; if silent, emit nothing; otherwise one line.
3. If `muted_until` is set, schedule a one-time task at that local time to delete `mute.json` (or write `{}`), and tell the operator the auto-unmute time.
4. An explicit "unmute" deletes `mute.json` immediately.

Precedent: 2026-07-30 bit 2 (prefilter dewpoint) mute ahead of a sorbead swap; 2026-08-16 liquefaction-wide 12 h mute requested by Vinay.
